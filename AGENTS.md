# Project instructions

- Keep HTML structure, CSS, and JavaScript in separate files. Do not add inline styles, script bodies, or event handlers to HTML.
- Inspect `git status` before making changes and preserve unrelated work.
- Save a local Git checkpoint of affected files before changing an existing implementation. If the working tree is clean, the current commit is already the checkpoint. Review staged contents; exclude credentials and private photographs.
- After completing and validating a change, save it in a small, descriptive local commit. Keep unrelated changes separate so individual changes can be undone.
- When asked to undo work, restore or revert the recorded version directly. Preserve current work before overwriting it; do not reconstruct an earlier implementation from memory.
- The `baseline` tag identifies the restored linear-addition version saved when Git was introduced. It is a reference point, not a claim of accurate analogue-film reproduction.
- The overall website name is undecided; the double-exposure tool is one part of a larger interactive artwork. The user leads wording, photo selections, page counts, and layouts, and wants straightforward HTML/CSS they can edit themselves. Keep help targeted and do not invent a site name or artistic copy.
- Google setup and Version 1 deployment are complete. Keep the current `EXPOSURE_*_ID` properties; do not repeat the old-folder migration. The deployed version uses the owner import page, but the user prefers dropping base photos directly into Drive. Folder-based intake is not implemented and no broader permission has been requested; resolve the access trade-off before changing that workflow.
